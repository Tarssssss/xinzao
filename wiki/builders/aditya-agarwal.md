# Aditya Agarwal（South Park Commons GP，前 Dropbox CTO）

South Park Commons 普通合伙人，前 Dropbox CTO。言论特点是大厂工程管理 + 投资双重视角下的硬判断：一边推动组织全员上手 AI coding，一边对当前 agent 产品成熟度评价很低——两条并不矛盾，是「看好方向、对现状挑剔」的并行立场。

## 立场与主张

### AI coding 的组织采用
- 一手组织数据点：SPC 全团队每周写代码，两个月前还只有一两个人。变化四条：全员自动化心态、各环节延迟变低、人聚焦角色里有意思的部分、野心范围爆炸式扩大（2026-04-09-spc-everyone-codes）。
- 启动条件是先让每个人上手 AI coding（他的说法 AI coding-pilled）；瓶颈在文化和习惯而非工具。收尾很硬：公司不做这件事就是真的在错过。

### Agent 的本质与产品成熟度
- agent 本质是代码生成 + 迭代式工具调用的包装，和「生成式 AI」标签关系不大；理解这个循环后，一次性 chat 更像一次搜索查询，always-on、能维持状态的 agent 吸引力远大于它（2026-04-30-agent-reality-check）。
- 对成熟度不客气：多数对 OpenClaw、HermesAgent 赞不绝口的人没真用过；agent 今天是开发者产品，愉悦感/简洁性/可靠性离消费级很远；装 OpenClaw 像 2000 年代初装 Linux。判断基于大量一手安装调试，不是转述。
- 点名的机会方向：agent 少给 chat、多生成动态界面（交互式应用和网页），猜测是下一个大创新方向；装机体验是另一个现成机会。

### 早期招聘
- 四条硬线，共同逻辑是用「意愿」做早筛而非能力履历：在大厂/大实验室和 pre-B 之间犹豫的人直接停止接触；不接受相对大厂约 70% 现金降薪的人会不开心；谈 offer 过程本身是考察环节，有新信息就别怕走开；创业没有 work-life balance（2026-05-22-aditya-agarwal-early-stage-hiring）。
- 注意这是个人经验式强主张，反映他对早期投入度的偏好，不是普适结论。
