# 写稿规范

> 本规范由 2026-06-10 的一次中文写稿规则 A/B 盲评产生：tars-writing 规则 vs 项目原有规则，4 条素材 × 3 位评委（扫描视角 / 编辑视角 / 事实核查视角），tars-writing 以 9:3 胜出，三个维度（事实保真、决策辅助、中文质感）均分全部领先。本文以 tars-writing 为骨架，合并了评委确认的 baseline 真实优点（summary 信息覆盖、content 的编辑增量、可执行收尾）。这是每日写稿 agent 的唯一写作指南，不再依赖其他规则文档。
>
> 文中所有示例均摘自这次评测的真实稿件。

## 0. 产品定位与读者

- 这是一个帮读者跟踪 AI builder 言论动向的中文日报站。读者痛点是 X 噪音太大，注意力优化是核心理念。
- 读者预设是已经懂 AI 行业背景的同行：不铺垫、不解释常见术语、不替读者总结他们本来就懂的事。
- 每条 story 的字段：
  - `title`：中文平实陈述句，准确概括这条动态讲了什么。
  - `summary`：50-90 字中文。性质是「决策辅助」而非内容缩写——读者读完要能在 30 秒内判断"这条值不值得我点开原文"。要传达：核心观点是什么、有什么新信息或判断、对什么人有用。
  - `content`：2-4 段中文，比 summary 完整，保留判断、背景和可操作含义。
  - `sourceLinks`：至少保留一个原始链接；多源合成的 story 可以保留多个。

## 1. 顶层心智

1. **写作目标是把一件事想清楚地转述给同行，不是让人想读下去**。钩子、悬念、storytelling、命名 takeaway 概念，全部和这个目标冲突。
2. **事实保真是第一权重**。这个站的信任建立在"转述可被原文核验"上。评测里输掉的版本几乎都是栽在这一条：编造数字、把希望写成预期、把陈述写成确认。
3. **AI 写中文的默认模式是反向的**：自动加修辞、对仗、过渡，把 tradeoff 压成确定因果，把 hedge 磨平。写这类稿要主动反向用力。
4. **篇幅匹配源材料的信息量**。一条推文撑不起四段就写三段。发现自己在加"故事"或重复论点，是源不够撑篇幅的信号，砍篇幅而不是注水。
5. **允许且鼓励一步编辑增量**（结构综合、对从业者的含义、可执行清单），但必须标注为编辑推断、加对冲词、且不超出素材能支撑的范围。详见第 2、5 节。

## 2. 事实保真红线（优先级最高，逐条自查）

这些是评测中真实出现、直接导致落败的失真模式：

1. **不编造素材外的具体信息**。数字、排名、热度、"首发"，没有就是没有。
   - 反例：「这条推文的热度（8.1K 赞）也部分来自这层身份」——素材里没有任何互动数据。
   - 反例：「Karpathy 首发评价 Fable 5」——原文没说这是首评。
2. **保留原文的不确定性等级**。hopefully ≠ 预期，may ≠ 会。
   - 原文 "can hopefully be tuned"：写「他希望后续能调」；不写「他预期后续会逐步调松」（确定性预测 + 凭空加的"逐步"）。
3. **程度比较不改写成首次发生**。
   - 原文 "it's never felt this tempting"：写「从来没有哪个版本让他这么想完全不看代码」（对）；不写「他第一次觉得'完全不看代码'有诱惑力」（错，含义不同）。
4. **动词不升格**。原文是陈述就写陈述：不把转述写成「确认」「亲口确认」，除非原文真的在确认一件此前存疑的事。
5. **引申要标注、对冲、收敛**。
   - 标注：用「顺着这个逻辑」「对 builder 的含义是」「这等于说」明示这是编辑推断，不冒充原话。
   - 对冲：用「可能」「如果真的」。好例：「过去需要在系统 prompt 里反复强调的工程纪律……**如果真的**成了模型的默认行为，agent 的 prompt 和 harness 还可以再简化一层」。
   - 收敛：归纳不要盖过例子能支撑的范围。原文说 "rework"（重做）就不要写成「删掉」；例子清单里有不符合"一次性使用"的项，就不要归纳成「共同点是高度定制甚至一次性使用」。
6. **不窄化原文概念**。"thought and design partner" 压成「产品设计伙伴」丢了 thought 这一半，属于失真。
7. **保留源的受众限定与犹疑语气**。原文有 "For those just starting to test Fable" 就保留「给刚开始测试 Fable 的用户」；原文带 "I think" 的回忆不要写成确定的因果归因。
8. **立场校准**。内部人评价自家产品，必须标注立场并指出哪部分可核验。好例：「这条评价来自 Anthropic 内部，立场上自然偏向自家模型。其中可以核验的部分是对行为的描述……可以照这个描述在自己的工作流里验证一遍。」

## 3. title 写法

规则：

- 平实陈述句，无钩子无 drama，不用「X 评价 Y：……」的冒号快讯体。
- 装进这条动态的**边际信息**——发言者的新判断、最有信息量的结论——而不是发布日人尽皆知的官方事实。
- 准确优先于抓人：宁可平实，不可窄化或拔高原意。

对照（均来自评测）：

| 好 | 差 | 差在哪 |
|---|---|---|
| Karpathy 认为 Claude Fable 5 是大版本级别的进步，长难题求解提升最明显 | Karpathy 评价 Claude Fable 5：与 Mythos 同底座，定性提升相当于一次大版本跳跃 | 差版把一半篇幅给了「同底座」这个零增量的已知事实；「大版本跳跃」是 version bump 直译，中文自然说法是「配得上大版本号的进步」 |
| Dan Shipper：AI 让昨天的专家能力变便宜，但同质化产出会推高对专家的需求 | Dan Shipper：AI 让昨天的专家能力变便宜，对真专家的需求反而上升 | 好版把因果机制（同质化产出）带进了标题；差版只标了转折没给原因 |

边界案例（两条教训同时成立）：「Boris Cherny 认为 Fable 5 把 Claude 从 coding agent 变成了产品设计伙伴」比「感受最明显的一次模型升级」信息量大——后者是每次发版都有的通用句式；但它把 "thought and design partner" 窄化成了「产品设计伙伴」。结论：**优先选有信息量的判断做标题，但转述必须完整，宁可稍长**。

## 4. summary 写法（50-90 字，决策辅助）

summary 是读者的 30 秒决策入口，是整条 story 里最重要的字段。

规则：

1. **开头直接回答"这条的增量是什么"**。好例：「Karpathy 判断 Fable 5 不止跑分领先……」——一句话框定为什么值得看这条而不是看跑分新闻。不要先铺已知事实（「同底座加护栏，benchmark 全面 SOTA」）再把新判断挤到句中。
2. **做优先级排序，不做等权压缩**。
   - 好例：「Albert 同时给出四条 Fable 使用建议，**关键的两条**：为旧模型写的 CLAUDE.md 和 skills 会把 Fable 锚定在过时模式，应该重写；从下发任务改成描述目标和验证方式。」——替读者排了序，还给了排序理由（锚定机制）。
   - 反例：「交更大的任务、默认开高 effort、重写为旧模型写的 skill 和 CLAUDE.md、从布置任务改成描述目标」——四条标签的顿号长串，是字段定义明确排除的「内容缩写」。
3. **尽量集齐四个要素**：核心判断/新信息、最有新闻价值的细节、负面信息或立场提示、具体受众句。满分案例（90 字内全齐）：「Claude Code 作者的一手判断：Fable 5 是 Opus 4.5 以来最明显的提升，调试时会自己加日志、验证修好后才报告完成，**且这不来自提示词**。属内部人评价，可作为是否把复杂任务交给模型的参考。」
4. **不漏掉素材里唯一的一手信息**。评测中唯一输掉的一条，败因就是 summary 漏了「agent 离人越远越不值钱」这个来自实际运营的一手数据点。被略去的应该是低信息量的常规建议，不是最有判断价值的那条。
5. **不浪费字数**：不重复 title 已有的信息；署名身份（"Every CEO Dan Shipper 提出"）若 title 已有就不再占字数。
6. **受众句要说清价值在哪**。好例：「在考虑换主力模型的人值得点开」「重度 Claude Code 用户值得对照检查自己的配置」。反例：「对正在评估新模型编码能力的人有直接参考价值」——"有直接参考价值"不增加任何信息，是套话。
7. 字数严格控制在 50-90 字内。

## 5. content 写法（2-4 段）

推荐结构：**事实与核心判断 → 例证与机制 → 立场校准 + 可操作含义**。

规则：

1. **删零信息导语**。「Karpathy 在 X 上评价 Claude Fable 5 的发布」这种句子对注意力优化产品是该砍的第一句。第一段直接进事实。
2. **每段要有增量，论点不说两遍**。评测中有版本第三段说「旧指令会把 Fable 锚定在过时的工作模式上」、第四段又说「沿用旧指令可能反而限制新模型的发挥」——同一个点两遍，第二遍是注水。
3. **鼓励一步编辑增量**（这是 baseline 版本被评委反复点赞的地方，前提是遵守第 2 节红线）：
   - 结构综合：「第四条和第一条指向同一个方向：任务尺度变大之后，交付方式也要跟着变。」
   - 对从业者的含义：「过去需要在系统 prompt 里反复强调的工程纪律……如果真的成了模型的默认行为，agent 的 prompt 和 harness 还可以再简化一层。」
   - 可执行收尾：「正在迁移到 Fable 的用户可以先做两件事：把 effort 默认值调高，再过一遍现有的 CLAUDE.md 和 skill。」「可以趁这次额度重置，把自己的配置重新过一遍。」
   - 重新评估式收尾：「顺着这个逻辑，以前不值得写的一次性工具，现在可以重新评估。」
4. **金句优先直接引语**。「让 AI 做一件事，它先惊艳你，让你觉得自己要被取代了，然后它停下来，回头问你：接下来该做什么？」比间接转述更有信息张力，且转述会损失原句节奏。
5. **末段做"怎么用这条信息"**：立场提示 + 可核验部分 + 行动建议。参考 Boris Cherny 条的末段写法（见第 2 节第 8 条）。
6. **分层叙述帮扫读**：「前两条比较直接……后两条改的是协作方式，信息量更大」这类分组句是好的；「先看 X」「回到主题」这类 AI 过渡是坏的。
7. 好的衔接句来自消化素材，不是过渡胶水。好例：「Brandon 在对谈里描述的体验是同一件事的日常版本。」

## 6. 中文语感

### 6.1 直译反例表（评测中真实扣分项）

| 差（直译/翻译腔） | 好 |
|---|---|
| benchmark 全面 SOTA 且领先有差距（by a margin） | 全面 SOTA 且领先幅度明显 |
| 定性提升够一次大版本跳跃（version bump） | 配得上大版本号的进步 |
| 把任务给得更大、更有野心（ambitious tasks） | 给它比旧模型更大、更难的任务 |
| effort 开 xhigh 以拿到最好的表现（for best performance） | 默认用 xhigh effort，效果最好 |
| 借这个时点 | 借这次重置 / 配合这次重置 |

### 6.2 英文术语的处理

- 行业通名直接保留：benchmark、agent、prompt、session、CLAUDE.md、effort、SOTA。
- 有现成中文的概念必须译：judgement → 判断力，taste → 品味。「表现出以前没有的 judgement、taste 和 dimensionality」这种成串未译英文读起来像没翻完的稿子。
- 不偷懒夹英：「且有 margin」这类写法不用。
- 没有准确中文对应的原词（如 "big model smell"）可保留并加一层说明。

### 6.3 名词化还原成动词

| 差（名词化） | 好（动词化） |
|---|---|
| 在广告变现上的能力积累 | 在广告变现上有较强的能力 |
| 与这一目标的对应关系更直接 | 能更好地满足这个目标 |
| 用户对答案中立性的怀疑 | 用户开始怀疑答案是否中立 |

自查信号：句子里出现「X 的 Y 关系/方式/结构/积累/程度」，多半在玩名词化。

### 6.4 不发明概念

不为"显得有洞察"造名词。评测反例：「防御性资产从既有技能转移到对当下情境的判断力」——"防御性资产"是原话里没有的概念包装。要表达概念，用通用术语 + 直接陈述。

### 6.5 禁用句式

- 重要论证句不用「不是 X 而是 Y」对仗。
- 不用疑问句、反问句（含段首和结尾）。
- AI 过渡句一律删：「先看 X」「把 X 放一边」「讲到这里」「回到主题」。
- 不替读者赋值：「大家都觉得」「常见的反应是」——转成自己的观察或删掉。
- 不用散漫词：「挺不一样的」「实打实」「更顺」「更对路」。语态是"平静地把一件事讲清楚"，不是"和朋友吐槽"。

### 6.6 标点

- 中文段落全用全角标点（，。：；！？""''（））。
- 数字和英文单词两侧留空格：「50-90 字」「AI builder 的」。

## 7. 选稿与去重（简要）

- 优先收录有明确观点、方法论、产品发布或 builder insight 的内容；跳过只有一句玩笑、没有上下文的帖子。
- 同一天同一 builder 连发多条相关帖子，合并成一条 story。
- 主链接已出现在旧 story 中的不重复收录；只是轻微补充的，更新旧 story 而不是新增。

## 8. Self-check 清单（每条 story 写完后按序过一遍）

1. **保真**：每个数字、每个"确认/首发/第一次"，能在原文找到出处吗？hedge 等级和原文一致吗？
2. **引申**：所有超出原文的判断都标注了「含义是/顺着这个逻辑」并加了对冲词吗？归纳没有盖过例子范围吗？
3. **title**：是平实陈述句吗？装的是新判断还是已知事实？有没有窄化原意？
4. **summary**：50-90 字内。开头是不是这条的增量？做了优先级排序还是等权压缩？四要素（核心判断、关键细节、caveat/立场、受众）缺了哪个？有没有漏掉唯一的一手信息点？受众句具体吗？
5. **content**：第一句有信息量吗？有没有论点说两遍？末段有立场校准和可操作含义吗？
6. **语感**：搜名词化结构、直译搭配、未译英文串、AI 过渡、疑问句、「不是 X 而是 Y」、自造概念词。
7. **标点**：全角统一，英文数字两侧留空格。
8. **篇幅**：源材料撑得起这个长度吗？在加 storytelling 就砍。
